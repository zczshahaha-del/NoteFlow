# 知流记忆的写入、纠正与读取

2026-11-22，关联开发问题 AI-10、AI-14、AI-18。前半部分记录初始审查和目标，末节记录本地实现与验收范围。

## 改动前复现

- 默认 Hindsight 路径把用户消息交给引擎提取。明确保存与自动整理大体共用该流程。应用拥有用户和来源，部分分类写在整段来源上，单条事实可能没有可稳定匹配的字段。参见 [记忆写入入口](../../server/app/memory/agent.py) 和 [来源处理](../../server/app/memory/gateway.py)。
- 网关读取时先取语义召回结果，再检查账号、来源、状态和已知分类。记录缺少规范键时仍可能进入精确查询。写入时按文本做去重，语义相同或相互否定的记录可能同时有效。用户手动修改一条后，现有规则会让后续自动提取的事实普遍进入待确认，包括与修改无关的事实。
- 用仓库现有的参考引擎和隔离数据库运行正式网关，两个用例均复现上述问题。参考引擎会返回宽召回结果，验证的是应用有没有裁决机制。用户截图反映了真实聊天中的冲突，本轮没有核查其账号的来源原文和时间，因此无法确定每条旧记录当时为何进入记忆。
- 上一轮原型尝试从称呼原句和引擎生成的句式匹配。真实聊天接口的一轮测试通过，另一次 Hindsight 输出合法的不同措辞时匹配失败。该原型已撤出，代码和实际记忆数据均保持在审查前状态。

## 先定规则，再选存储

每条可用记忆都要回答几个问题：是谁的、从哪句话来、在什么范围有效、什么时候生效、是否被纠正或撤销。用户原话和系统解释分别保存或通过来源引用关联。来源来自服务端，模型可以提出候选和值，不能指定账号、扩大作用域或决定生效时间。

| 记忆 | 例子 | 如何处理 |
| --- | --- | --- |
| 当前只有一个值 | 希望被怎么称呼、目前常住地、某项目使用的数据库 | 按主体、规范字段和范围管理，同一组最多一个当前版本。清晰的更新替换当前值，旧版本供核对或查历史 |
| 能同时成立的多项 | 喜欢的书籍类型、正在学习的技术 | 合并同义项，保留不同项。只有明确说某项停止或取消时，才撤下对应项 |
| 带时间的经历 | 上个月参加了一次面试 | 作为经历保留时间。当前岗位、求职状态等问题读当前值，询问过去发生了什么才读经历 |
| 会话或任务上下文 | 这篇用英文、当前草稿下一节写什么 | 由本轮或任务状态管理，随范围结束失效。引用、假设、测试、角色扮演及助手生成内容不能直接成为个人事实 |

字段注册表只收录产品明确支持的稳定字段。姓名与偏好称呼是两个字段。全局偏好和某篇笔记、某个项目的偏好也各自生效。未知主题可作为有来源的经历或候选，不能与某个已有字段模糊匹配后直接覆盖。首版在少量已定义字段上跑通规则，再根据实际问法扩展字段。

## 写入与纠正

1. 对本轮已提交的用户原话提取一次结构化候选。候选用统一动作表达新增、纠正、撤销，并携带字段、值、适用范围和可核对的证据片段。模型负责理解不同说法，服务端负责校验授权、来源、安全规则及字段约束。无法定位纠正对象时保留原状态，必要时问一句。
2. 用户直接改设置，或在对话中作出足够明确的更新，可变为当前值。自动推断、引用和临时要求不能覆盖已确认值。低确定性、相同可信度的矛盾保留待确认。只隔离对应字段和范围的候选，其他独立的长期偏好照常处理。
3. 对当前只有一个值的字段，在同一 PostgreSQL 事务里记录修订并切换当前指针。唯一键使用用户、主体、范围和字段。幂等写入绑定服务端消息 ID，更新顺序依据消息接收顺序或已确认的生效时间。重试和晚完成的后台任务不能把旧版本升回当前。
4. 查询、暂时要求和敏感信息不生成长期记忆。异步整理可以排队。明确要求保存时，以事务提交且查得到为成功条件；处理中或服务失败如实提示。停用、撤销或删除当前值后，旧值不会自动恢复成当前值。保留版本与彻底删除各走自己的生命周期。

## 读取与回答

- **问当前值**。例如「我现在住哪」「以后怎么称呼我」。先按类型、字段、账号和范围精确读取当前有效版本。短期指令可影响这次对话，长期默认值通过明确更新改变。若问法确实分不清是想查姓名还是偏好称呼，按问题解释或澄清。
- **问历史或开放问题**。例如「我以前在哪工作」「我看书有什么习惯」。用语义召回找候选，再验证归属、来源、状态、适用时间和范围。历史记录可以解释发生过什么，不能借检索分数重新变为当前事实。涉及某个已有当前字段时，答案上下文只给适用的当前值，除非用户明确问历史。
- **做任务**。只读取与任务相关的少量偏好。当前明确要求先生效，再看更具体范围的已确认默认值，最后才看全局默认值。笔记问答只使用允许的资料范围。历史聊天可以帮助理解「刚才那段」等指代，历史里已被纠正的说法不当作当前资料再次注入。
- **结果有四种**。查到有效事实、没有记录、有冲突待确认、暂时读不到。普通聊天的可选个性化读取失败可以继续回答。明确查询和管理操作报告实际状态。摘要从同一份生效结果生成，用户需要时再查看旧版本及依据。

## 推荐架构与代价

继续放在同一个后端。TurnPlanner 管这一轮想干什么，记忆服务管哪些候选能生效和能否被读，聊天、润色、生成和设置共用记忆服务的结构化接口。回答模型用这些结果组织回复。

建议让 PostgreSQL 成为**已确认、可更新的结构化记忆**的唯一事实源。Hindsight 继续整理和检索长尾经历。若给结构化事实接语义索引，索引只返回候选 ID，读回 PostgreSQL 确认当前版本后才能用。Hindsight 官方将 Recall 描述为语义相似度和关联检索，可以借它找候选，具体哪个版本当前有效由知流自己的产品规则决定。[Hindsight Recall](https://docs.hindsight.vectorize.io/api-reference/recall-memories/) · [PostgreSQL 约束](https://www.postgresql.org/docs/16/ddl-constraints.html)

这个方案调整了第一版由 Hindsight 统一保管正式事实的决定。好处是明确更新可在本地一次提交，下次读取可以直接用，也能约束并发。代价是要维护一小套字段契约、修订记录及一次迁移。两个存储可以共存，每类数据只有一个写入权威。迁移时对已纳管字段切断旧引擎结果作为当前值的入口，避免两边反复覆盖。已有存储、来源、适配器和删除屏障可复用。暂时没有理由拆微服务、引入新引擎或为每类问题单独加提示词分支。

## 实施和验收顺序

1. 先为当前行为和目标状态建立独立评测。至少包含下表各场景的中文改写、不同对话及组合场景，分别检查候选和最终回答。
2. 用同一套版本和作用域规则实现少量当前字段，先打通新对话确认、显式纠正及精确读取，再接语义召回的过滤和设置摘要。评测输入与正式模型使用相同调用链，单元测试另控并发与故障。
3. 对已有数据只读演练，按来源和范围分出明确可迁、冲突不确定、曾停用或已删除。明确候选也要做来源核对和预览。切换停止旧路径写入纳管字段，保存迁移映射核对启用、删除状态及数量。出现二义性不按时间或出现次数猜当前值。切换后再产生的新修订、撤销或删除需要被保留，回滚方案也必须覆盖。

| 验收用例 | 应看到的结果 |
| --- | --- |
| 明确更新称呼、城市、项目配置后，在新对话换一种问法 | 取对应范围的当前值。历史问法能区分有效时间 |
| 提供两个并存兴趣，再取消其中一个 | 只影响一个兴趣 |
| 明确说是在测试、引用他人、或「只这篇用英文」 | 不覆盖任何长期值 |
| 修订写作偏好后，正常分享新的学习兴趣 | 新兴趣按它自己的规则处理 |
| 两个会话并发修订，旧任务更晚完成又被重试 | 始终只有一个当前值，顺序及重试正确 |
| 停用、删除或关闭记忆，索引仍回传旧记录，另一账号同时查询 | 旧记录和跨账号数据不进入回答 |
| 有冲突、服务不可用、明确从未保存 | 三种结果分别处理，普通提问仍能回答，管理操作不虚报成功 |
| 问当前值时旧会话历史仍提到相反说法 | 当前答案使用同一份已确认值，设置摘要与新对话一致 |

## 本地实现与验收

正式聊天以服务端保存的用户发言为依据。明确保存立即排队并等待结果，普通聊天可在后台合并同一会话内相近的几轮。每次最多查看当前发言前 32 条、自动整理时再看后 8 条，并限制文本长度。后续澄清可帮助放弃候选，新的事实必须归到实际表态的用户发言。跨会话读取近期有效事实和按主题检索的旧事实，需要时带上对应原话。系统不会逐轮通读所有历史会话。

模型提出事实、证据、范围和修订关系。服务端检查原话与消息归属，按账号串行更新受影响的事实，并校验版本先后。实现复用来源表的结构化元数据和已有队列；规范字段优先复用，新的主题允许模型提出字段，当前没有独立的全局字段注册表。新事实由 PostgreSQL 决定当前内容和状态，Hindsight 提供索引。真实变化保留可查询的过去值，明确的测试值退出现值与历史答案。证据不足的建议可跳过。

删除前可预览受影响的来源；删除时撤下当前及其相连的旧版本，屏蔽已删证据和旧任务，清除专属索引文档。原会话里的聊天原文仍可由用户查看。旧来源缺少消息编号时使用较保守的时间边界。已有账号的历史记忆尚未批量迁移。

本地使用合成账号、新建六个真实会话，从网页同用的 HTTP 聊天接口发起请求，经真实模型、工作队列、PostgreSQL 和 Hindsight 验证：

- 前一轮讨论给小标题加「青竹标记」，下一轮只确认「按刚才的方案」，第三个会话能复述偏好，来源里同时能找到讨论与确认。一次性修改没有改掉长期偏好。
- 旧会话记苏州，新会话更新到宁波。另两个会话分别追问当前和过去常住地，均答对。
- 删除当前城市后，给原搬家消息另建队列任务，实际处理后没有新事实。回看旧对话后再开新会话，也没有报出两个城市。写作偏好仍存在，日常提到的画流程图习惯可继续自动写入。
- 在另一会话明确将测试标签「海蓝」纠正为「松针」。查询只回答「松针」，当前列表没有「海蓝」。补测同时覆盖在提示先打开笔记后紧接着更正记忆。
- 可复跑的入口是 `server/tests/memory_dialogue_http_smoke.py --url http://127.0.0.1:5173`，在仓库 Python 环境中设置 `PYTHONPATH=server`。测试自行建立并清理合成账户。手动新增、来源和图谱的正式接口另由 `server/tests/memory_hindsight_http_smoke.py` 覆盖。

上述运行结果限于当前本机和这些真实问法。表中的全量改写、旧账号全库迁移、长期负载及生产环境仍待验证。
