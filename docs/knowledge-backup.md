# 知识库备份与恢复

设置 → 数据管理：

- **导出知识库备份**：JSON v2，从服务端一致快照读取当前账号的全部笔记（含回收站）、目录、正文、标签、收藏、置顶、原始时间、版本历史及附件实体。导出前同步本机待保存正文；离线或同步失败时拒绝生成可能漏掉修改的备份。附件丢失或校验失败也会拒绝导出。
- **导出 Markdown 文件**：目录和正文的 ZIP，便于其他软件阅读。不是完整恢复包，不包含属性、版本和附件实体。
- **导入笔记文件**：每次选择一份 JSON / ZIP / Markdown。v2 JSON 按整批事务导入；旧 JSON v1 保留其已有目录和属性，普通 ZIP 按路径建立目录。聊天、长期记忆、运行中的 AI 草稿、账号、会话和密钥不属于知识库备份。

导入只追加，不覆盖现有笔记。目标 ID 空闲时保留笔记和目录 ID，冲突时分配新 ID 并改写内部引用；附件总是分配新 ID，正文和版本中的附件地址一起改写。恢复后通过任务重建检索索引，索引完成前搜索可能暂未包含新笔记。

服务端只在数据库事务提交后返回成功。网络响应丢失时使用界面中的“重试导入”，同一请求 ID 不会重复创建。停止重试并不撤销可能已提交的导入，须刷新确认结果。关闭页面会丢失本次重试标识；重新选择文件视为新的一次追加。

单次文件上限 25 MB，最多 500 篇笔记、500 个目录、5000 个版本和 500 个附件；单篇 Markdown 8 MB，单附件沿用服务端上传限制。超限明确报错，不截断数据。ZIP 按实际解压量、声明大小和 CRC 校验，不信任中央目录的大小声明。历史备份中包含当前禁止的活动附件时会整体拒绝导入，不静默丢弃。

接口：登录后的 `GET /api/knowledge-backup`、`POST /api/knowledge-backup/import`；后者要求 `X-Import-Id`，只使用当前会话账号，不接受备份内提供的用户或存储路径。文件内容不会写入导入回执和日志。

附件上传和导入在写文件前持久化清理意图，事务失败或进程中断后由 outbox 清理未引用对象；删除记录与清理任务同事务提交。重试耗尽进入 `integration_outbox.status=dead`，需运维检查文件权限 / 磁盘问题后重新排队，不能把永久存储故障当作成功清理。附件内容只向当前所有者会话开放，历史 `sig` URL 不再提供匿名读取权限。
